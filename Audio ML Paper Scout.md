## **Comparative Ranking of Top Project Candidates**

TIGER (ICLR 2025\) ranks first as the primary recommendation for a single-student, four-week project due to its parameter efficiency, sub-second execution, and lightweight installation requirements3. Weighing approximately 3.5 MB for the tiny variant and under 15 MB for the small checkpoint, TIGER loads into memory instantly and operates under 500 MB of unified RAM on Apple Silicon7. The official repository features a standalone inference entry point (inference\_speech.py) that executes cleanly on PyTorch CPU and Metal Performance Shaders (MPS) backends without custom CUDA requirements10. This architecture enables zero-latency live audio demonstrations where overlapping vocal tracks are isolated in real time, while establishing a comparison against a classical Non-negative Matrix Factorization (NMF) or STFT Wiener-filtering baseline9. The single biggest risk associated with TIGER lies in its sensitivity to non-stationary ambient noise and acoustic room reverberation, as the primary model checkpoints are trained on simulated clean mixtures (Libri2Mix), which may cause minor vocal leakage when processing live microphone inputs recorded in non-treated room environments7.  
WavTokenizer (ICLR 2025\) ranks second, providing an effective framework for projects centered on discrete neural audio codecs and acoustic tokenization1. The model compresses 24kHz audio signals down to 40 or 75 discrete tokens per second using a single codebook architecture, eliminating multi-codebook residual cascades while maintaining high spectral reconstruction fidelity1. The inference pipeline exposes clear Python primitives (encode\_infer() and decode()), enabling straightforward execution on Apple Silicon M4 Pro hardware in approximately 0.20 seconds per 5-second sample13. Reconstructing high-fidelity speech and music from a compact vector of 40 integer indices per second offers an effective live demonstration, readily evaluated against classical Opus or Griffin-Lim baselines using standard PESQ and STOI metrics1. The single biggest risk for WavTokenizer stems from its strict input sample rate constraints (24 kHz mono), requiring precise real-time audio resampling pipelines to prevent high-frequency aliasing or pitch distortion during live microphone playback1.  
FlowDec (ICLR 2025\) ranks third, offering a strong option for full-band 48 kHz general audio reconstruction powered by conditional flow matching2. By combining non-adversarial encoder-decoder training with a stochastic postfilter, FlowDec eliminates GAN-induced spectral artifacts and achieves stable convergence in 6 numerical ordinary differential equation (ODE) steps2. The provided Jupyter notebook (demo.ipynb) runs directly on PyTorch MPS and CPU devices without mandatory CUDA extensions, achieving an inference latency of under 0.80 seconds on an M4 Pro22. Comparing FlowDec against an Opus codec baseline at equivalent bitrates (4.5 kbps and 7.5 kbps) provides an audible demonstration of high-frequency detail restoration across speech, music, and environmental soundscapes22. The single biggest risk for FlowDec involves its complex multi-library software dependencies—including audiotools and hydra-core—which require careful dependency pinning to prevent installation conflicts on macOS Arm64 python environments19.

## **Execution Strategy and Experimental Methodology**

Project execution begins in Week 1 with environment initialization on macOS Arm64 using Python 3.10 within a Conda virtual environment13. Core dependencies—including PyTorch with native MPS support, Torchaudio, SciPy, Librosa, and standard evaluation packages (pesq, pystoi, torchmetrics)—are installed to establish a stable local execution path7. The chosen candidate repository is cloned locally, and pre-trained checkpoint weights are verified by executing default test scripts on CPU and MPS backends to confirm memory allocation and operational stability10.  
Week 2 focuses on constructing the classical, non-deep baseline module to satisfy rigorous benchmark comparison requirements9. For speech separation tasks, an NMF baseline is implemented using sklearn.decomposition.NMF on STFT magnitude spectrograms, alongside an STFT Wiener filter implemented via scipy.signal9. For neural codec tasks, an Opus compression baseline is scripted via ffmpeg wrapper calls at identical bitrates, or a Griffin-Lim phase recovery baseline is built using librosa.griffinlim. A unified Python benchmarking script is developed to ingest input audio files, run both the classical baseline and the neural model, and compute matching metric scores—such as Scale-Invariant Signal-to-Distortion Ratio (SI-SDR), Perceptual Evaluation of Speech Quality (PESQ), or Short-Time Objective Intelligibility (STOI)—into structured JSON logs9.  
Week 3 shifts to custom dataset collection and batch quantitative evaluation9. A localized dataset comprising 20 to 30 custom audio recordings is generated using a laptop microphone across diverse acoustic settings, including clean speech, multi-speaker crosstalk, ambient background noise, and instrument clips7. Automated evaluation scripts process the custom dataset through both the classical baseline and the neural model, logging metric scores, peak unified memory consumption, and per-sample processing latency9. Statistical summaries and comparative mel-spectrogram plots are generated to illustrate empirical performance gains under varied acoustic environments9.  
Week 4 centers on building an interactive graphical application for live presentation and demonstration7. A web interface constructed using Gradio or Streamlit allows live audio capture directly from the microphone or real-time file upload. The interface provides one-click execution that routes input signals through both the classical baseline and the deep learning model simultaneously, rendering side-by-side waveform displays, mel-spectrogram visualizations, objective metric scores, and synchronized audio playback controls. This deployment structure delivers a clear, interactive live demonstration within a 10-minute presentation context7.
